# Music_Game_Redo

这是面向 STC89C52RC（Keil 中用兼容的 AT89C52 目标）和普中开发板的 LCD1602 音游工程。打开 `Music_Game_Redo.uvproj` 即可在 Keil5 中继续调试。

选歌页沿用音乐播放器的操作方式：K1（P3.1）上一首，K3（P3.2）下一首，K2（P3.0）开始。游戏结束后按 K2 或 K4 返回选歌页。

游戏中的四行从上到下对应实物按键从右到左：

| LCD 行 | 实物按键 | 端口 |
| --- | --- | --- |
| 上 | K4 | P3.3 |
| 上（第二行） | K3 | P3.2 |
| 下（第一行） | K2 | P3.0 |
| 下 | K1 | P3.1 |

每个音符占 3×4 像素，从左向右移动约 1.92 秒到达第 12 个字符的中心像素列。Perfect 使用 x=55..57，Great 使用 x=54 或 x=58；这正好对应音符三列与判定线重合或相邻。游戏输入采用独立按键的多键采样，因此谱面中的上下半区双键可以同时判定。刷新周期为 16 ms，单帧最大移动 1 像素；击中后音符立即消失，并在判定线对应的 4 像素行闪烁 96 ms 的反馈条（Perfect 为实心条，Great 为虚线条）。

每首歌的谱面只选取对应音乐表中的真实非休止音符起点。第一首 MKDR 保留前半段（1635 个节拍单位），现在有 90 个音符；第二首有 102 个音符。计分使用有理数累计，AllPerfect 最终固定为 1000000，其他结果按整数四舍五入；结算页显示分数、歌曲名和 D/C/B/A/S/V/Phi 评级。

Timer1 中断只维护 1 ms 音乐时钟和 4 ms 游戏时钟，不再在中断中调用音乐状态机。前台 `Music_Run()` 按绝对截止时间推进声音/休止相位，因此 LCD 刷新即使短暂占用主循环也不会把歌曲越播越慢，同时避免中断栈与 LCD/按键代码重入造成重复音符、停音或误结束。音符表终止符和音高索引也有边界保护。LCD 游戏画面采用 CGRAM 和 DDRAM 差分刷新，无变化的像素帧不会关闭蜂鸣器定时器，以减少间歇卡顿。

命中时音符立即从场上移除；判定线显示闪烁条，LCD 右下角同时显示 `P`（Perfect）或 `G`（Great），反馈持续约 96 ms。

已用 Keil C51 编译器、BL51 链接器和 OH51 生成 `Objects\Music_Game_Redo.hex`；自检结果为 0 error、0 warning，程序代码占用 7795 bytes、data 占用 229.3 bytes，低于 STC89C52RC 的 8 KB 程序空间和 256-byte 内部 RAM。硬件实机仍建议重点观察 LCD1602 的 CGRAM 刷新速度、P2.5 蜂鸣器与 LCD RW 共用时的声音间隙，以及 P3.2 红外接收干扰。
